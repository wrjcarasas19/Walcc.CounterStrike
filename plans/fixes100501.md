# Client/Server Networking Fixes — Plan

Date: 2026-10-05 · Branch: `improve-client-server-networking`

Follow-up to the networking review. Steps 1 (client hardening) and Part A (building
the server from source) are done; this plan covers the remaining 13 items in
priority order. Numbers in brackets (`#6`) match the review findings.

Server changes all live in `src/server/sfu.go` and only reach production through
the Go build stage restored in commit `89669fc`.

## Phase 1 — Protect the live server

### 1.1 Stop unauthenticated slot exhaustion [#6]
**Problem:** `websocketHandler` reserves one of 128 slots (`connections.Add`,
`sfu.go:287`) as soon as a WebSocket opens, before any WebRTC exists, and
`CheckOrigin` accepts every origin (`sfu.go:32`). 128 idle sockets lock out all
players.

**Change:**
- Allocate the slot in `writeChannel.OnOpen` (both data channels open) instead
  of up front; `ReadLoop` gets its IP once the slot exists.
- Cap concurrent WebSockets per remote IP (e.g. 4) using
  `X-Forwarded-For`-unaware `r.RemoteAddr` (no proxy in front today).
- Restrict `CheckOrigin` to the page's own host (allow an env override such as
  `ALLOWED_ORIGINS` for local dev).
- Close sockets that haven't completed WebRTC within 30s.

**Verify:** script opening 130 WebSockets from one IP → only the cap succeeds;
a browser client still connects; slot count returns to 0 after disconnects.

### 1.2 Session lifetime tied to WebRTC, not signaling [#3]
**Problem:** cleanup is `defer`red behind `c.ReadMessage()` (`sfu.go:389`); if
the signaling socket drops (idle proxy/NAT), the player is kicked even though
the data channels are fine.

**Change:**
- Send WebSocket pings every 20s with a read deadline + pong handler.
- Drive teardown from `OnConnectionStateChange` (`failed`/`closed`) and close
  the WebSocket from there; a WebSocket close alone no longer closes the peer
  once it is connected.

**Verify:** connect, kill the WebSocket (DevTools → close), game keeps running;
close the tab → server frees the slot within the ICE timeout.

## Phase 2 — What players notice

### 2.1 Connect when the player clicks Connect [#7]
**Problem:** `engine.init()` (which includes `connect()`) runs at **Download**
(`main.ts:39`), so idle launchers hold server slots and a link lost during the
download is only logged (`webrtc.ts:120`), making **Connect** silently dead.

**Change:**
- Split `Xash3DWebRTC.init()` into engine init (wasm) and `connect()`.
- Call engine init during the download; call `connect()` from the `ready` →
  Connect action, showing a "Connecting…" state and the error on failure.
- After connect, surface a lost connection to the player (overlay or reload
  prompt) instead of only `console.warn`.

**Verify:** sit on the Ready screen → no server slot in use; block port 27018 →
clicking Connect shows an error within 20s.

### 2.2 Version the game-files cache [#8]
**Problem:** IndexedDB key is the constant `'gamefiles.zip'`
(`gamefiles.ts:5`) while the URL is versioned (`gamezip_8308.zip`); a new zip
is never fetched by returning players.

**Change:** key the cache by `GAMEFILES_URL`; on a miss, delete other
`gamefiles*`/old-URL keys before storing.

**Verify:** load once, change the URL, reload → new download; old entry gone in
DevTools → Application → IndexedDB.

### 2.3 Show the real failure reason [#10]
**Problem:** every failure shows "Failed to load game. Please try again later."
(`main.ts:46`).

**Change:** map known errors to messages — download HTTP status, signaling
WebSocket refused/closed, WebRTC timeout ("UDP port 27018 may be blocked") —
falling back to the generic text.

**Verify:** stop the server → launcher says it can't reach the server; bad zip
URL → launcher shows the download error.

## Phase 3 — Rest of the server cleanup

### 3.1 Remove the unused voice-chat SFU [#1]
**Change:** delete the audio transceiver (`sfu.go:263`), `trackLocals`,
`addTrack`/`removeTrack`, `signalPeerConnections` re-offer loop and
`DefaultSignalsCount` (`sfu.go:56`), `dispatchKeyFrame` and its 3s ticker
(`sfu.go:187`, `sfu.go:525`), the `OnTrack` handler, and now-unused imports
(`rtp`, `rtcp`). Send one offer per connection.

**Verify:** offer SDP contains only `m=application`; client connects; no
renegotiation messages after the first answer.

### 3.2 ICE-TCP fallback [#2]
**Change:** next to `SetICEUDPMux` (`sfu.go:498`), add
`settingEngine.SetICETCPMux(webrtc.NewICETCPMux(nil, tcpListener, 8))` on the
same `PORT`, and enable `NetworkTypeTCP4` in `SetNetworkTypes`. The compose
files already publish `27018/tcp`.

**Verify:** offer includes a `tcptype passive` candidate; with UDP 27018
blocked (e.g. `pfctl`/firewall rule) the client still connects.

### 3.3 Non-blocking ReadLoop [#4]
**Change:** replace `packets <- …` (`sfu.go:228`) with a `select` that drops the
packet when the 256-slot channel is full (count drops for logging).

**Verify:** `go vet`; game plays normally; under a flood test the server
keeps serving other clients.

### 3.4 Slot reuse race [#5]
**Change:** give each slot a generation counter (or store a per-connection
token) so `Replace`/`Remove` (`sfu.go:317`, `sfu.go:321`) only act on the slot
they own. Largely subsumed by 1.1 if the slot is allocated in `OnOpen`; keep the
guard anyway.

**Verify:** unit test on `FixedArray`: Remove → Add (reuse) → stale Replace is
rejected.

## Phase 4 — Polish

### 4.1 Reduce peak memory while downloading [#9]
**Change:** when `Content-Length` is known, write chunks into one preallocated
`Uint8Array` instead of `chunks[]` + concat (`gamefiles.ts:28-50`); release
references before `loadAsync`.

**Verify:** Chrome DevTools memory timeline shows ~1 copy of the zip during
download instead of 2.

### 4.2 Static asset caching and compression [#11]
**Change:** replace `os.Stat` + `filepath.Join` + `http.ServeFile`
(`sfu.go:477-482`) with `http.FileServer(http.Dir("public"))`; add
`Cache-Control: public, max-age=31536000, immutable` for `/assets/*` (Vite's
hashed output) and gzip for `.wasm`/`.js`/`.css`.

**Verify:** second page load serves wasm from cache; `curl -H 'Accept-Encoding:
gzip'` returns compressed `xash.wasm`.

### 4.3 Sanitize nickname [#12]
**Change:** strip `"`, `;` and control characters and cap length (31) before
`name "${playerName}"` (`main.ts:86`); apply the same rule to the input field.

**Verify:** nickname `a"; quit; "` joins with that text as the name and no
`quit` runs.

### 4.4 Build hygiene [#13]
**Change:**
- `.dockerignore`: add `.git`, `dist`, `*.zip`, `plans`, `src/client/dist`.
- Drop `apt upgrade -y` from the engine stage (`Dockerfile:5`).
- Remove the unused `GIT_AUTH_TOKEN` secret (`deploy.yml:80-81`).
- Mirror `goxash3d-fwgs` and the engine commit into an owned GitHub account and
  point `GOXASH3D_REPO` / `XASH3D_REPO` at them.

**Verify:** `docker buildx build --platform linux/amd64 .` succeeds; build
context size drops.
